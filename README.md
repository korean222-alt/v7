# WORKOS

청소·인테리어 업체용 모바일 운영 도구. 고객·견적·일정·미수금을 한 곳에서 본다.

```bash
npm install
npm run dev      # 로컬 (AI 기능은 Vercel 함수가 없어서 동작 안 함)
npm run build
```

## AI 제공자 설정

`/api/chat` 하나가 모든 AI 호출을 받는다. 프런트는 Anthropic Messages 형식으로
보내고 `data.content[0].text`로 읽는데, 그 계약을 유지한 채 서버에서만 제공자를
바꾼다. 그래서 `App.jsx`는 손대지 않고 환경변수만으로 갈아탈 수 있다.

**그래서 `App.jsx`가 보내는 `model: "claude-…"`는 Gemini 경로에서 그냥 버려진다.**
계약을 유지하려고 남겨둔 껍데기일 뿐, 실제 모델은 아래 후보에서 고른다.
코드에 Claude 이름이 보인다고 Claude를 부르는 게 아니다 — 헷갈리기 쉬운 지점이다.

Vercel 프로젝트 설정 → Environment Variables:

| 변수 | 값 | 설명 |
|---|---|---|
| `AI_PROVIDER` | `gemini` | 기본값. `anthropic`으로 바꾸면 되돌아간다 |
| `GEMINI_API_KEY` | (Google AI Studio 키) | 필수 |
| `GEMINI_TEXT_MODEL` | (비워둠) | 특정 모델을 강제할 때만 |
| `GEMINI_VISION_MODEL` | (비워둠) | 위와 같음 |
| `ANTHROPIC_API_KEY` | — | `AI_PROVIDER=anthropic`일 때만 |

### 모델 이름은 박아두지 않는다

모델을 하드코딩하면 구글이 갈아치울 때마다 앱이 멈춘다. 실제로 겪은 일이다.

- `gemini-2.0-*` → 2026년 6월 셧다운
- `gemini-2.5-flash-lite` → "신규 사용자에게 더 이상 제공되지 않음"

그래서 `/api/chat`은 이렇게 고른다.

1. 최근에 성공한 모델 (기억해둔다)
2. 정적 후보: `3.6-flash` → `flash-latest` → `3.5-flash` → `2.5-flash` → `1.5-flash`
3. 그래도 다 막히면 `GET /v1beta/models`로 이 키가 쓸 수 있는 목록을 받아
   **버전 높은 순으로 끝까지** 시도

**성공한 모델은 기억해서 다음 요청은 거기서 바로 시작한다.** 이게 없으면
매 요청마다 못 쓰는 모델부터 다시 두드려서 요청이 5배로 뛴다.

### 429는 두 가지 뜻이다 (중요)

`429 RESOURCE_EXHAUSTED`가 항상 "다 썼다"는 뜻이 아니다.

| 응답 | 실제 의미 |
|---|---|
| 429 + `limit: 0` | **이 키로는 그 모델을 쓸 권한이 없음.** 사용량 0이어도 즉시 429 |
| 429 + `limit: 1500` 등 | 진짜로 하루 한도를 다 씀 |

무료 티어에 최신 모델이 없는 계정이 많다. 그런 키로 `3.5-flash`를 부르면
한 번도 안 썼는데 429가 온다. 이걸 "오늘 사용량이 다 찼어요"라고 안내하면
멀쩡한 한도를 두고 하루를 기다리게 된다. 그래서 `isQuotaZero()`로 갈라서
안내 문구를 다르게 준다.

**그리고 이때 필요한 건 기다림이 아니라 내려가기다.** 정적 후보 끝에
`1.5-flash`가 있는 이유가 이것이다 — 낡았지만 대부분의 무료 키에서 살아 있고,
카톡에서 이름·전화번호를 뽑는 데는 충분하다.

### 무료 한도는 프로젝트 단위다 ⚠️

사용자 1명당이 아니라 **API 키 하나 기준**이다.

| 모델 | 분당 | 하루 |
|---|---|---|
| gemini-3.5-flash | 15회 | 1,500회 |

앱은 사용자 1명에게 하루 68회(사진 8·상담 40·카톡 추출 20)를 허용한다.
**하루 20명 정도가 한계**고, 넘으면 모두가 429를 받는다.
분당 15회 제한도 있어서 여러 명이 동시에 쓰면 순간적으로 막힐 수 있다.
한도가 차면 화면에 "오늘 AI 사용량이 모두 찼어요"가 뜬다.

파일럿 규모(1~5명)에선 이 정도가 편하다. 사람이 늘면 이 숫자를 다시
줄이거나 유료 티어로 올려야 한다 — 무료라고 무한은 아니다.

### 모델이 붐빌 때 · 429를 스스로 만들지 않는다

무료 티어는 인기 모델이 자주 붐빈다("This model is currently experiencing
high demand"). 그때 그냥 실패하면 사장님 눈에는 앱이 고장난 것과 구분이 안 된다.

다만 재시도는 실패 종류를 가려서 해야 한다. 처음엔 429도 "잠깐 뒤엔 될 수
있다"고 보고 재시도했는데, **429는 0.9초 기다린다고 안 풀린다.** 오히려 모델
후보마다 재시도가 붙어서 한 번의 사용자 액션이 요청 8~9개로 부풀었고,
분당 15회 한도를 스스로 태웠다.

- **503·500·504(서버 순간 장애)** → 같은 모델로 0.9초 뒤 한 번 더
- **429** → 로컬 재시도 없이 바로 다음 모델로
- 성공한 모델은 기억 → 그다음부터는 요청 1개

### 끝까지 가는 것보다 제때 포기하는 게 낫다

후보를 끝까지 훑게 만들었더니 이번엔 함수가 제한 시간을 넘겼다. 그러면
Vercel이 JSON이 아닌 오류 페이지를 돌려주고, 앱은 그걸 파싱하다 사파리에서
`The string did not match the expected pattern`으로 죽는다. 사장님 입장에선
한참 기다린 끝에 알 수 없는 영어가 뜨는 셈이라 최악이다.

그래서 예산을 건다.

| 값 | 기본 | 환경변수 |
|---|---|---|
| 전체 제한 시간 | 12초 | `AI_DEADLINE_MS` |
| 시도할 모델 수 | 정적 후보 +1 | `AI_MAX_MODELS` |

남은 시간이 3초 미만이면 더 시도하지 않고 "다시 한 번 눌러주세요"로 끝낸다.
두 번째 시도는 기억해둔 모델부터 가니 훨씬 빠르다.

**모델 수를 정적 후보보다 작게 잡으면 안 된다.** 4로 박아뒀더니 후보 5개 중
마지막 `gemini-1.5-flash`까지 못 갔다. 무료 키의 마지막 보루로 일부러 맨 뒤에
둔 모델인데 한 번도 안 불렸고, 시도 횟수가 이미 한도라 목록 조회로 내려가는
길까지 같이 막혔다. 안 되는 모델은 404·429로 즉시 돌아오니 몇 개 더 두드리는
비용은 작다 — 진짜 방어선은 횟수가 아니라 시간 예산이다.

### 기다려서 될 일과 사람이 손대야 할 일

`429`만 갈라서는 부족했다. 키가 틀렸거나(400) API가 꺼져 있으면(403) 다시
눌러도 영원히 안 되는데, 화면에는 "잠시 뒤에 다시 시도해주세요"가 떴다.
사장님은 하루 종일 같은 버튼을 누르고, 우리는 고장난 걸 모른 채 지나간다.

| 상태 | 안내 |
|---|---|
| 400·401·403 | "AI 열쇠(키) 설정에 문제가 있어요… 관리자에게 알려주세요" |
| 404 | "쓸 수 있는 AI 모델을 찾지 못했어요" |
| 500·503·504 | "AI 서버가 지금 붐벼요. 잠시 뒤에" |
| 429 | 위의 두 갈래 |

문구 끝의 `(코드 400)`은 사장님 보라는 게 아니라 전화로 불러줄 수 있으라고 붙였다.

### 안 될 때 먼저 볼 곳 — `GET /api/chat`

브라우저로 `https://<도메인>/api/chat`을 그냥 열면 점검 결과가 JSON으로 나온다.
무료 플랜은 런타임 로그가 **1시간**만 남아서, 연락받고 볼 때쯤이면 이미 지워져 있다.

```jsonc
{ "keySet": true, "ok": true,
  "chain": [...],    // 앱이 실제로 두드릴 순서
  "usable": [...] }  // 이 키로 진짜 쓸 수 있는 모델
```

- `keySet: false` → 환경변수가 없다
- `ok: false, status: 400` → 키가 틀렸다 (새로 발급)
- `ok: false, status: 403` → 키 제한 또는 API 비활성
- `chain`의 모델이 `usable`에 하나도 없다 → `GEMINI_TEXT_MODEL`에 `usable` 중 하나를 박는다

모델 목록 조회라 생성 한도를 쓰지 않는다. 키 자체는 응답에 담기지 않는다.

앱 쪽도 `askAI()` 하나로 모았다. `res.json()`을 바로 쓰면 JSON이 아닌 응답에
그대로 터지므로, 텍스트로 받아 파싱을 시도하고 실패하면 한국어 안내로 바꾼다.

### 어떤 모델이 되는지 알았다면 고정해라

`GEMINI_TEXT_MODEL`에 실제로 되는 모델(예: `gemini-1.5-flash`)을 박아두면
후보를 훑지 않고 바로 그 모델로 간다. 요청 1개, 응답 1~2초.
무료 티어에 최신 모델이 없는 키라면 이게 가장 빠르고 확실하다.

### 개인정보 주의 ⚠️

카톡 추출 기능은 **고객 이름·전화번호·주소**를 AI로 보낸다.
구글 무료 티어는 입력 데이터를 제품 개선에 쓸 수 있으므로,
**돈을 받고 서비스하는 단계에서는 반드시 유료 티어로 전환**한다.
(유료 티어는 학습에 사용하지 않는다.)

## 데이터 저장

`localStorage`만 쓴다. 서버도 로그인도 없다.

- 장점: 링크만 열면 바로 쓴다. 가입 절차가 없어서 이탈이 적다
- 단점: **폰을 바꾸거나 인터넷 기록을 지우면 전부 사라진다**

그래서 `더보기 → 데이터 백업`에 내보내기/불러오기를 넣어뒀다.
실사용자에게 줄 때는 이 기능을 반드시 안내한다. 고객관리 도구가 데이터를
날리면 그건 불편이 아니라 사고다.

## 빈 화면 대응

처음 열면 모든 숫자가 0이라 "내가 이걸 다 입력해야 하는구나" 하고 닫기 쉽다.
그래서 두 군데에 예시 데이터 버튼을 뒀다.

- 온보딩 3단계
- 홈 화면 (고객·견적·일정이 모두 비었을 때)

온보딩에서 `건너뛰기`를 누르면 3단계를 안 거치는데, 이탈 위험이 큰 쪽이
바로 그 사람들이라 홈에도 같은 버튼을 둔 것이다.

예시는 `더보기 → 데이터 백업 → 비우기`로 한 번에 지운다.
