# WORKOS

청소·인테리어 업체용 모바일 운영 도구. 고객·견적·일정·미수금을 한 곳에서 본다.

```bash
npm install
npm run dev      # 로컬 (AI 기능은 Vercel 함수가 없어서 동작 안 함)
npm run build
```

## AI 제공자 설정

`/api/chat` 하나가 모든 AI 호출을 받는다. 프런트는 Anthropic Messages 형식으로
보내고 `data.content[0].text`로 읽는데, 그 계약을 유지한 채 서버에서만 제공자를
바꾼다. 그래서 `App.jsx`는 손대지 않고 환경변수만으로 갈아탈 수 있다.

Vercel 프로젝트 설정 → Environment Variables:

| 변수 | 값 | 설명 |
|---|---|---|
| `AI_PROVIDER` | `gemini` | 기본값. `anthropic`으로 바꾸면 되돌아간다 |
| `GEMINI_API_KEY` | (Google AI Studio 키) | 필수 |
| `GEMINI_TEXT_MODEL` | (비워둠) | 특정 모델을 강제할 때만 |
| `GEMINI_VISION_MODEL` | (비워둠) | 위와 같음 |
| `ANTHROPIC_API_KEY` | — | `AI_PROVIDER=anthropic`일 때만 |

### 모델 이름은 박아두지 않는다

모델을 하드코딩하면 구글이 갈아치울 때마다 앱이 멈춘다. 실제로 겪은 일이다.

- `gemini-2.0-*` → 2026년 6월 셧다운
- `gemini-2.5-flash-lite` → "신규 사용자에게 더 이상 제공되지 않음"

그래서 `/api/chat`이 이 순서로 버틴다.

1. `gemini-flash-latest` — 버전이 안 박힌 별칭. 구글이 알아서 최신 GA를 가리킨다
2. `gemini-3.5-flash` → `gemini-3.6-flash`
3. 그래도 전부 막히면 **`GET /v1beta/models`로 실제 목록을 조회해서** 쓸 수 있는
   flash 모델을 찾아 쓴다 (한 번 찾으면 재사용)

붐빔(503)·한도(429) 같은 일시적 실패는 0.9초 뒤 한 번 더 시도하고,
키 오류처럼 다시 해도 똑같은 실패는 재시도 없이 다음 후보로 넘어간다.

**즉 다음에 구글이 또 이름을 바꿔도 코드를 안 고쳐도 된다.**

### 무료 한도는 프로젝트 단위다 ⚠️

사용자 1명당이 아니라 **API 키 하나 기준**이다.

| 모델 | 분당 | 하루 |
|---|---|---|
| gemini-3.5-flash | 15회 | 1,500회 |

앱은 사용자 1명에게 하루 34회(사진 4·상담 20·카톡 추출 10)를 허용한다.
**하루 40명 정도가 한계**고, 넘으면 모두가 429를 받는다.
분당 15회 제한도 있어서 여러 명이 동시에 쓰면 순간적으로 막힐 수 있다.
한도가 차면 화면에 "오늘 AI 사용량이 모두 찼어요"가 뜬다.

### 모델이 붐빌 때

무료 티어는 인기 모델이 자주 붐빈다("This model is currently experiencing
high demand"). 그때 그냥 실패하면 사장님 눈에는 앱이 고장난 것과 구분이 안 된다.
그래서 `/api/chat`이 이렇게 버틴다.

1. 같은 모델로 0.9초 뒤 한 번 더
2. 그래도 안 되면 `gemini-2.5-flash` → `gemini-2.5-flash-lite` 순으로 내려감
3. 전부 실패하면 "AI 서버가 지금 붐벼요. 잠시 뒤에 다시 눌러주세요."

키 오류처럼 다시 해도 똑같은 실패는 재시도하지 않고 바로 넘어간다.

파일럿(1~3명)에는 넉넉하지만, 늘어나면 유료 티어로 올려야 한다.

### 개인정보 주의 ⚠️

카톡 추출 기능은 **고객 이름·전화번호·주소**를 AI로 보낸다.
구글 무료 티어는 입력 데이터를 제품 개선에 쓸 수 있으므로,
**돈을 받고 서비스하는 단계에서는 반드시 유료 티어로 전환**한다.
(유료 티어는 학습에 사용하지 않는다.)

## 데이터 저장

`localStorage`만 쓴다. 서버도 로그인도 없다.

- 장점: 링크만 열면 바로 쓴다. 가입 절차가 없어서 이탈이 적다
- 단점: **폰을 바꾸거나 인터넷 기록을 지우면 전부 사라진다**

그래서 `더보기 → 데이터 백업`에 내보내기/불러오기를 넣어뒀다.
실사용자에게 줄 때는 이 기능을 반드시 안내한다. 고객관리 도구가 데이터를
날리면 그건 불편이 아니라 사고다.

## 빈 화면 대응

처음 열면 모든 숫자가 0이라 "내가 이걸 다 입력해야 하는구나" 하고 닫기 쉽다.
그래서 두 군데에 예시 데이터 버튼을 뒀다.

- 온보딩 3단계
- 홈 화면 (고객·견적·일정이 모두 비었을 때)

온보딩에서 `건너뛰기`를 누르면 3단계를 안 거치는데, 이탈 위험이 큰 쪽이
바로 그 사람들이라 홈에도 같은 버튼을 둔 것이다.

예시는 `더보기 → 데이터 백업 → 비우기`로 한 번에 지운다.
